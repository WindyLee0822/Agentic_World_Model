Read-Grounded World Model — how the agent & WM interact “Ours”

Official τ² orchestrator runs unchanged; the single tool-execution chokepoint environment.get_response is rerouted through the world model. The real DB is never mutated — only the finally-selected trajectory is committed.

Two failure surfaces: ACTING (the agent acts on WM-predicted observations, ①②) and SELECTING (the verifier ranks on its own beliefs, ③). The next pages dissect six failures and ask: did the WM actually have enough information to get it right?

How to read the next 6 slides

Each slide shows one task as an abstracted trajectory: reads are collapsed, writes highlighted. b2 = the same gpt-4.1 agent acting on the real env (oracle-selected) — it succeeds, so its run is the de-facto reference. ours = agent acting inside the WM + WM verifier.

Attribution buckets
  • read-grounding limit  the WM only knows what was read; the real env validates globally. Not fixable without more reads.
  • agent-intrinsic  the decisive error is the agent’s choice; a perfect WM would not change the outcome.
  • WM error (info present)  the WM/verifier had the grounding (incl. gold actions) yet answered wrong.
  • verifier false-positive  broken trajectory stamped SUCCESS.
